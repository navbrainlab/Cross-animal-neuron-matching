# Mechanism analysis protocol aligned to the main Benchmark

This document is subordinate to `UNIFIED_BENCHMARK_PERTURBATION_PROTOCOL.md`.

## Current dataset split

The main Benchmark uses `cv5_grouped_v1`, generated by
`neurid/mprt_net/experiments/make_grouped_folds.py` with split seed
`20260823`.

- The generator pools records from the source `train`, `val`, and `test`
  directories before repartitioning them. The old source split is retained only
  as provenance and is not the outer-CV assignment.
- Atanas contains 38 records/groups. Its automatic group key is
  `recording_uid`; the five buckets contain 8, 8, 8, 7, and 7 recordings.
- RLD contains 95 records/groups. Its group key is `subject_id`; every bucket
  contains 19 animals.
- Groups are shuffled deterministically and greedily assigned to the bucket
  with the smallest recording load, then the smallest supervised-identity
  load. This balances fold size and labeled-neuron count.
- For outer fold `f`, bucket `f` is test, bucket `(f + 1) mod 5` is validation,
  and the remaining three buckets are training. Consequently every group is
  test exactly once and validation exactly once.
- The static atlas is built from that fold's training split only. Checkpoint
  selection uses validation only. Test is used once for the locked report.

The name "grouped" refers to the stored biological group key. It does not mean
that acquisition calendar dates are held out as intact groups. In particular,
Atanas uses `recording_uid`, and its manifest explicitly carries the generator
warning that repeated recordings from one biological animal must be checked if
that distinction matters to a new claim.

## Reporting contract

Mechanism analyses that support the main Benchmark must use:

1. the exact `Data/*/cv5_grouped_v1/fold_{0..4}` membership;
2. the static Full arm used by the clean Benchmark;
3. model seed 42 only;
4. the complete method-native test cohort, with no robustness common-cohort
   filtering;
5. one value per biological fold and the unweighted mean ± sample SD across
   five folds; and
6. a fold-by-fold Clean gate against
   `runs/fair_identity_seed42_benchmark_v1/benchmark_seed42_fold_cells.csv`.

Any mechanism analysis that reports or stratifies Top-1 must consume the
locked held-out per-query predictions from those same CV5 × seed-42 runs.
Re-running inference with a different cohort, candidate set, evaluator, Full
arm, or seed does not qualify, even if the aggregate accuracy is close. Legacy
CV5 × three-seed mechanism packages remain provenance only.

For the Full arm, query count, Top-1, Top-5, and Hungarian accuracy must match
with absolute tolerance `1e-12`; MRR may use `5e-8` to accommodate CPU/GPU
floating-point reduction differences.

The current compliant component-ablation summary is generated with:

```bash
python -m scripts.mechanisms.summarize_component_ablation_benchmark_seed42
```

Its authoritative outputs are under
`runs/mprt_v1_1_component_ablation_benchmark_seed42_v1/`.

## Why Robustness Clean did not match

The v2 Robustness table reports a shared corruption-manifest/common-query
cohort and retains unrepresentable labels as incorrect. Its Clean gate targets
saved `current-grouped` replay artifacts before common-cohort rescoring, not
the current main Benchmark fold table. That makes it a paired corruption
analysis but not a reproduction of the main clean table. Therefore its Clean
row must not be used as the mechanism-analysis baseline.
